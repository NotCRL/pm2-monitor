pm2 monitor

New to pm2? Click "guided setup" at the top: it checks what is missing and walks you through installing and starting everything, step by step.

Step-by-step guide to install Node.js, pm2 and this monitor on Linux, macOS and Windows: docs/INSTALL.md in the repository.

Getting started

  1. On startup the monitor looks for the pm2 daemons on this computer (~/.pm2* folders, PM2_HOME and running daemons). If one is missing, "daemons" → "add" accepts its PM2_HOME folder; "scan" repeats the search.
  2. Each row is a process: click the row to see its logs; buttons start / stop / restart it.
  3. Processes without a domain are listed under "No domain". Create a domain with "+ domain" or from a row's drop-down.

Domains and start order

  • A domain groups processes, even from different daemons (e.g. a database, a backend and a frontend).
  • The "ord" column is the start order: lower numbers start first. "start all" waits for each process to be online (and stay so for 2 s) before starting the next; if one does not start within the maximum wait (⚙, default 30 s) the sequence stops and says so.
  • "stop all" shuts down in reverse order. "restart" = stop everything, then start in order.
  • Processes that were saved but are no longer in the daemon (or whose daemon is stopped) can still be started: the monitor remembers how to launch them. "✕" next to a "not started" process forgets it.

Notifications and logs

  • The bell in the header shows what happened (an app crashed, stopped, restarted by itself, a daemon went down...) and lets you choose, for each domain, what you want to be told about (errors, warnings, good news), how (the bell menu, browser notification, sound, desktop notification) and an optional memory limit.
  • Notifications are produced while the monitor is running. Changes you make through the monitor itself (a stop, a restart) are not reported.
  • Two logs side by side: click ⧉ in a log panel to open a second one next to it (at most two). The next process you click is shown in the active panel, the one underlined in blue. Drag the bar between the list and the logs, and the bar between the two logs, to resize them; double-click a bar to reset it.
  • Folder: the folder column shows where a process runs; click it to open the folder in your file manager (the monitor asks your system to open it), or use the small ⧉ button to copy the path. ⚙ Settings > Columns hides the columns you do not need.
  • Type and labels: the type column says whether a process is a backend or a frontend; pm2 monitor guesses it ("auto: …") and you can change it, or choose "+ new type…" to create your own. Click the ＋ next to a name to give the process labels (any number, each with its own colour); Types and labels… (⚙ Settings, or the bar above the list) renames, recolours and deletes them. The bar above the list filters by type and by labels.
  • Links: the links column shows where a running app answers (for example localhost:3000); click it to open the page. To list only real web pages, pm2 monitor sends one harmless web request to each port an app listens on; the switch is in ⚙ Settings.
  • Groups: click a group's title to collapse or expand it ("Collapse all" / "Expand all" above the list); the choice is remembered. The ⚙ Settings menu holds the page size and the language. In a log, A− / A+ change the size of the log text.
  • Turning it off: the power button (⏻) in the header turns pm2 monitor off. Your apps keep running under pm2. To start it again, double-click Start pm2-monitor (.bat on Windows, .command on macOS, start-pm2-monitor.sh on Linux).
  • In the logs panel, ⤒ jumps to the first line and ⤓ to the last one (and follows new lines again); the ◧ / ⬓ button moves the logs to the right of the list or below it. The panel loads the last 400 lines by default (200, 400, 1000 or 2000 from the menu).
  • Filtering the log: type in the search box to keep only the lines that contain a word (not case-sensitive); the ERROR / WARN / INFO / DEBUG buttons keep only lines of those levels (a stack trace stays with its error); ±2 lines adds the lines around each result; Hide repeated lines folds identical lines into one with a counter (×N), ignoring timestamps; Copy and Save take exactly what you see.

Where the configuration lives

It holds known daemons, domains, order and how to relaunch processes. It is readable JSON you can edit by hand (while the server is stopped). To use another file:

  • command line: python3 server.py --config /path/to/config.json (a folder works too: config.json inside it is used)
  • or the PM2_MONITOR_CONFIG environment variable
  • default location: Linux ~/.config/pm2-monitor · macOS ~/Library/Application Support/pm2-monitor · Windows %APPDATA%\pm2-monitor

To move your settings to another computer, copy this file. Process environment variables are not saved; if one is needed to relaunch from scratch, add it by hand as "env": {...} in the process spec. You can also set "pm2Path" in the file to use a specific pm2.

Common problems

  • "pm2 not found": install pm2 (npm i -g pm2) or set its path in pm2Path in the config. pm2 in use:
  • "daemon stopped": that group's daemon is not running. Its processes are listed from the saved config and "start" also brings the daemon back.
  • A daemon is missing: add its folder from "daemons". On Windows running daemons are not discovered automatically.
  • "not online after Ns" during a domain start: check the process logs; if it is just slow, raise the maximum wait in ⚙.
  • The header turns red "NOT UPDATED": the server stopped answering; restart it.

Feedback and ideas

For a bug please include: operating system, Python and pm2 versions, what you expected and what happened. If you can, attach the terminal output of the server (without sensitive data).

Non conosci pm2? Clicca "configurazione guidata" in alto: controlla cosa manca e ti accompagna passo passo nell'installazione e nell'avvio di tutto.

Guida passo passo per installare Node.js, pm2 e questo monitor su Linux, macOS e Windows: docs/INSTALL.it.md nella repository.

Primi passi

  1. All'avvio il monitor cerca da solo i demoni pm2 del computer (cartelle ~/.pm2*, PM2_HOME e demoni in esecuzione). Se ne manca uno, "demoni" → "aggiungi" accetta la sua cartella PM2_HOME; "scansiona" rifà la ricerca.
  2. Ogni riga è un processo: clic sulla riga per vedere i log, pulsanti per start / stop / restart.
  3. I processi senza dominio stanno in "Senza dominio". Crea un dominio con "+ dominio" o dal menu a tendina di una riga.

Domini e ordine di avvio

  • Un dominio raggruppa processi, anche di demoni diversi (es. un database, un backend e un frontend).
  • La colonna "ord" è l'ordine di avvio: numeri più bassi partono prima. "avvia tutti" aspetta che ogni processo sia online (e resti tale per 2 s) prima del successivo; se non parte entro il tempo massimo (⚙, default 30 s) la sequenza si ferma e lo segnala.
  • "ferma tutti" spegne in ordine inverso. "riavvia" = stop di tutti, poi start in ordine.
  • I processi salvati ma assenti dal demone (o con demone spento) si avviano lo stesso: il monitor ricorda come lanciarli. "✕" accanto a un processo "non avviato" lo dimentica.

Notifiche e log

  • La campanella nella testata mostra cosa è successo (un'app è andata in errore, si è fermata, si è riavviata da sola, un demone è caduto...) e ti lascia scegliere, per ogni dominio, di cosa vuoi essere avvisato (errori, avvisi, buone notizie), come (menu della campanella, notifica del browser, suono, notifica del desktop) e un limite di memoria facoltativo.
  • Le notifiche vengono prodotte mentre il monitor è in esecuzione. I cambiamenti che fai dal monitor stesso (uno stop, un riavvio) non vengono segnalati.
  • Due log affiancati: clicca ⧉ in un pannello dei log per aprirne un secondo accanto (al massimo due). Il prossimo processo che clicchi si apre nel pannello attivo, quello sottolineato di blu. Trascina la barra tra l'elenco e i log, e quella tra i due log, per ridimensionarli; doppio clic su una barra per ripristinarla.
  • Cartella: la colonna cartella mostra dove gira un processo; cliccala per aprire la cartella nel gestore dei file (è il monitor a chiedere al sistema di aprirla), oppure usa il piccolo pulsante ⧉ per copiare il percorso. ⚙ Impostazioni > Colonne nasconde le colonne che non ti servono.
  • Tipo ed etichette: la colonna tipo dice se un processo è un backend o un frontend; pm2 monitor lo indovina ("auto: …") e puoi cambiarlo, oppure scegliere "+ nuovo tipo…" per crearne uno tuo. Clicca il ＋ accanto a un nome per dare etichette al processo (quante vuoi, ciascuna con il suo colore); Tipi ed etichette… (⚙ Impostazioni, o la barra sopra l'elenco) le rinomina, ne cambia il colore e le elimina. La barra sopra l'elenco filtra per tipo e per etichette.
  • Link: la colonna link mostra dove risponde un'app in esecuzione (per esempio localhost:3000); cliccala per aprire la pagina. Per elencare solo le vere pagine web, pm2 monitor invia una richiesta web innocua a ogni porta su cui un'app è in ascolto; l'interruttore è in ⚙ Impostazioni.
  • Gruppi: clicca il titolo di un gruppo per comprimerlo o espanderlo ("Comprimi tutto" / "Espandi tutto" sopra l'elenco); la scelta viene ricordata. Il menu ⚙ Impostazioni contiene la dimensione della pagina e la lingua. In un log, A− / A+ cambiano la dimensione del testo del log.
  • Spegnere: il pulsante di accensione (⏻) nella testata spegne pm2 monitor. Le tue app continuano a funzionare sotto pm2. Per riavviarlo, fai doppio clic su Start pm2-monitor (.bat su Windows, .command su macOS, start-pm2-monitor.sh su Linux).
  • Nel pannello dei log, ⤒ va alla prima riga e ⤓ all'ultima (e torna a seguire le nuove righe); il pulsante ◧ / ⬓ sposta i log a destra dell'elenco o sotto. Il pannello carica di base le ultime 400 righe (200, 400, 1000 o 2000 dal menu).
  • Filtrare il log: scrivi nella casella di ricerca per tenere solo le righe che contengono una parola (senza distinguere maiuscole e minuscole); i pulsanti ERROR / WARN / INFO / DEBUG tengono solo le righe di quei livelli (uno stack trace resta con il suo errore); ±2 righe aggiunge le righe attorno a ogni risultato; Nascondi righe ripetute unisce le righe identiche in una con il contatore (×N), ignorando gli orari; Copia e Salva prendono esattamente ciò che vedi.

Dove sta la configurazione

Contiene demoni noti, domini, ordine e come rilanciare i processi. È un JSON leggibile e modificabile a mano (a server fermo). Per usarne un'altra:

  • da riga di comando: python3 server.py --config /percorso/config.json (anche una cartella: userà config.json dentro)
  • oppure con la variabile d'ambiente PM2_MONITOR_CONFIG
  • posizione predefinita: Linux ~/.config/pm2-monitor · macOS ~/Library/Application Support/pm2-monitor · Windows %APPDATA%\pm2-monitor

Per portare le impostazioni su un altro computer basta copiare questo file. L'ambiente dei processi (variabili d'ambiente) non viene salvato; se serve per un rilancio da zero va aggiunto a mano come "env": {...} nella specifica del processo. Dentro il file si può anche indicare "pm2Path" per usare un pm2 preciso.

Problemi comuni

  • "pm2 non trovato": installa pm2 (npm i -g pm2) o indica il percorso in pm2Path nella config. pm2 in uso:
  • "demone spento": il demone di quel gruppo non è in esecuzione. I processi restano elencati dalla config salvata e "start" fa ripartire anche il demone.
  • Un demone non compare: aggiungi la sua cartella da "demoni". Su Windows i demoni in esecuzione non si scoprono da soli.
  • "non online dopo Ns" durante un avvio per dominio: guarda i log del processo; se è solo lento, alza il tempo massimo in ⚙.
  • La testata diventa rossa "NON AGGIORNATO": il server non risponde più; riavvialo.

Segnalazioni e idee

Per un bug indica: sistema operativo, versione di Python e di pm2, cosa ti aspettavi e cosa è successo. Allega, se puoi, l'output del terminale dove gira il server (senza dati riservati).
