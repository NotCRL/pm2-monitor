Step-by-step guide to install Node.js, pm2 and this monitor on Linux, macOS and Windows: docs/INSTALL.md in the repository.


    
Getting started

    
    
      
  1. On startup the monitor looks for the pm2 daemons on this computer (~/.pm2* folders, PM2_HOME and running daemons). If one is missing, "daemons" → "add" accepts its PM2_HOME folder; "scan" repeats the search.
    2. 
      
  2. Each row is a process: click the row to see its logs; buttons start / stop / restart it.
    3. 
      
  3. Processes without a domain are listed under "No domain". Create a domain with "+ domain" or from a row's drop-down.
    4. 
    


    
Domains and start order

    
    
      
  • A domain groups processes, even from different daemons (e.g. a database, a backend and a frontend).
    • 
      
  • The "ord" column is the start order: lower numbers start first. "start all" waits for each process to be online (and stay so for 2 s) before starting the next; if one does not start within the maximum wait (⚙, default 30 s) the sequence stops and says so.
    • 
      
  • "stop all" shuts down in reverse order. "restart" = stop everything, then start in order.
    • 
      
  • Processes that were saved but are no longer in the daemon (or whose daemon is stopped) can still be started: the monitor remembers how to launch them. "✕" next to a "not started" process forgets it.
    • 
    


    
Where the configuration lives

    

    
It holds known daemons, domains, order and how to relaunch processes. It is readable JSON you can edit by hand (while the server is stopped). To use another file:

    
    
      
  • command line: python3 server.py --config /path/to/config.json (a folder works too: config.json inside it is used)
    • 
      
  • or the PM2_MONITOR_CONFIG environment variable
    • 
      
  • default location: Linux ~/.config/pm2-monitor · macOS ~/Library/Application Support/pm2-monitor · Windows %APPDATA%\pm2-monitor
    • 
    

    
To move your settings to another computer, copy this file. Process environment variables are not saved; if one is needed to relaunch from scratch, add it by hand as "env": {...} in the process spec. You can also set "pm2Path" in the file to use a specific pm2.


    
Common problems

    
    
      
  • "pm2 not found": install pm2 (npm i -g pm2) or set its path in pm2Path in the config. pm2 in use: 
    • 
      
  • "daemon stopped": that group's daemon is not running. Its processes are listed from the saved config and "start" also brings the daemon back.
    • 
      
  • A daemon is missing: add its folder from "daemons". On Windows running daemons are not discovered automatically.
    • 
      
  • "not online after Ns" during a domain start: check the process logs; if it is just slow, raise the maximum wait in ⚙.
    • 
      
  • The header turns red "NOT UPDATED": the server stopped answering; restart it.
    • 
    


    
Feedback and ideas

    

    
For a bug please include: operating system, Python and pm2 versions, what you expected and what happened. If you can, attach the terminal output of the server (without sensitive data).

  


  

    
Non conosci pm2? Clicca "configurazione guidata" in alto: controlla cosa manca e ti accompagna passo passo nell'installazione e nell'avvio di tutto.

    
Guida passo passo per installare Node.js, pm2 e questo monitor su Linux, macOS e Windows: docs/INSTALL.it.md nella repository.


    
Primi passi

    
    
      
  1. All'avvio il monitor cerca da solo i demoni pm2 del computer (cartelle ~/.pm2*, PM2_HOME e demoni in esecuzione). Se ne manca uno, "demoni" → "aggiungi" accetta la sua cartella PM2_HOME; "scansiona" rifà la ricerca.
    2. 
      
  2. Ogni riga è un processo: clic sulla riga per vedere i log, pulsanti per start / stop / restart.
    3. 
      
  3. I processi senza dominio stanno in "Senza dominio". Crea un dominio con "+ dominio" o dal menu a tendina di una riga.
    4. 
    


    
Domini e ordine di avvio

    
    
      
  • Un dominio raggruppa processi, anche di demoni diversi (es. un database, un backend e un frontend).
    • 
      
  • La colonna "ord" è l'ordine di avvio: numeri più bassi partono prima. "avvia tutti" aspetta che ogni processo sia online (e resti tale per 2 s) prima del successivo; se non parte entro il tempo massimo (⚙, default 30 s) la sequenza si ferma e lo segnala.
    • 
      
  • "ferma tutti" spegne in ordine inverso. "riavvia" = stop di tutti, poi start in ordine.
    • 
      
  • I processi salvati ma assenti dal demone (o con demone spento) si avviano lo stesso: il monitor ricorda come lanciarli. "✕" accanto a un processo "non avviato" lo dimentica.
    • 
    


    
Dove sta la configurazione

    

    
Contiene demoni noti, domini, ordine e come rilanciare i processi. È un JSON leggibile e modificabile a mano (a server fermo). Per usarne un'altra:

    
    
      
  • da riga di comando: python3 server.py --config /percorso/config.json (anche una cartella: userà config.json dentro)
    • 
      
  • oppure con la variabile d'ambiente PM2_MONITOR_CONFIG
    • 
      
  • posizione predefinita: Linux ~/.config/pm2-monitor · macOS ~/Library/Application Support/pm2-monitor · Windows %APPDATA%\pm2-monitor
    • 
    

    
Per portare le impostazioni su un altro computer basta copiare questo file. L'ambiente dei processi (variabili d'ambiente) non viene salvato; se serve per un rilancio da zero va aggiunto a mano come "env": {...} nella specifica del processo. Dentro il file si può anche indicare "pm2Path" per usare un pm2 preciso.


    
Problemi comuni

    
    
      
  • "pm2 non trovato": installa pm2 (npm i -g pm2) o indica il percorso in pm2Path nella config. pm2 in uso: 
    • 
      
  • "demone spento": il demone di quel gruppo non è in esecuzione. I processi restano elencati dalla config salvata e "start" fa ripartire anche il demone.
    • 
      
  • Un demone non compare: aggiungi la sua cartella da "demoni". Su Windows i demoni in esecuzione non si scoprono da soli.
    • 
      
  • "non online dopo Ns" durante un avvio per dominio: guarda i log del processo; se è solo lento, alza il tempo massimo in ⚙.
    • 
      
  • La testata diventa rossa "NON AGGIORNATO": il server non risponde più; riavvialo.
    •
